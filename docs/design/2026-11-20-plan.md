# sp500-factor-ml-portfolio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A live, self-updating long-only S&P 500 portfolio picked monthly by a LightGBM ranking model, with a walk-forward backtest, Fama-French attribution, SHAP explanation, a failure alert, a Streamlit app and a short deck.

**Architecture:** A Python package `factorml/` builds monthly tables from free sources (Wikipedia membership, Yahoo prices, SEC XBRL, Kenneth French factors) into parquet tables queried with DuckDB. `pipeline.py backfill` builds the full history once locally; `pipeline.py monthly` runs in GitHub Actions on days 1-3 of each month, passes quality gates, appends one live month and commits. The app and the deck read only committed tables.

**Tech Stack:** Python 3.13 (CI 3.12), pandas, numpy, duckdb, pandera, lightgbm, shap, statsmodels, yfinance, requests, lxml, streamlit, plotly, pytest, ruff; pptxgenjs (node) for the deck.

**Spec:** `docs/design/2026-11-20-design.md`

## Global Constraints

- Free data only; no API keys except the `SEC_CONTACT` repository secret (never in the repo; local value from `.env`).
- Long-only, top 50, equal weight, monthly rebalance, costs 10 bps per side on turnover (config).
- First feature month 2010-06; first out-of-sample month 2013-01; hyper-parameters frozen on 2010-2012.
- Benchmarks: `^SP500TR`; equal-weight universe; factor rule = mean rank of 12-1 momentum, gross profitability, book-to-market, top 50.
- Quality gates: prices for >= 95% of current members; |monthly return| <= 80% unless split/dividend explains it; members 495-510; month is closed; any gate failure stops before writing.
- Live record is append-only; backtest and live are always shown apart.
- Raw downloads are not committed; `data/snapshot/` holds derived monthly tables.
- Repo text in English, README ends with "Résumé en français"; sober theme (`.streamlit/config.toml` copied from `fpa-forecasting-copilot`), chart palette `["#2558A8","#B7791F","#1F9D55","#7C3AED","#C2362B","#0E9AA7","#E8590C","#DB2777"]`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; `.github/workflows/*` is never committed locally (created in the GitHub web editor).
- No background tasks during development; CI is polled in the foreground with a bounded loop.
- Skills per stage (design 6.10): financial-intelligence + academic-research + data:statistical-analysis (method and docs), test-driven-development and verification-before-completion (code), humanizer (all prose), dataviz (app charts), anthropic-skills:pptx (deck), code review before publishing.

## Review Focus

1. **Ticker changes and dual share classes** (FB->META, GOOG and GOOGL both members): a renamed company keeps one security id across the rename; two share classes are two members. Test in Task 2.
2. **A member stops trading mid-history** (acquired or delisted, no Yahoo prices): it is kept in the universe for the months it has prices, reported in the survivorship share, never forward-filled. Test in Task 3.
3. **Restated fundamentals** (the same period filed twice): the value used at month M is the latest one *filed on or before* M, so a restatement filed later never leaks back. Test in Task 4.
4. **The monthly job runs twice for the same month** (manual re-run after an alert, or cron days 2 and 3): the second run is a no-op and the live record gains no duplicate row. Test in Task 11.
5. **Yahoo returns a partial batch** (some tickers empty, no exception): the coverage gate fails, the run stops and the alert fires; nothing is committed. Test in Tasks 10 and 11.
